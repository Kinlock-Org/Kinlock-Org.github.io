The four repos

kinlock-contracts

The Soroban contract that actually holds and moves funds: registry and vault modules, tests, deploy scripts, generated TypeScript bindings.

kinlock-sdk

The TypeScript client every other layer talks to the contract through, plus the event indexer that mirrors chain data for lists.

TypeScript · v0.3.0 · GitHub ↗

kinlock-app

The Next.js web app: senders lock funds, payees claim them, anyone can verify a receipt.

The public, schema-validated list of verified payees, per country, bound to the on-chain record by a hash.

Non-negotiable principles

These hold across all four repos, not just the contract:

  • Chain is truth. Pages that move money read chain state directly, never a database cache.
  • Non-custodial. No service holds a user's keys or funds; only the contract does, under its own rules.
  • No privileged path to locked funds. Funds leave the contract only to the payout address snapshotted at creation, or back to the sender.
  • Honest receipts. A receipt proves payment to a verified payee. It is not proof the money was spent the way anyone expected.
  • Country-agnostic core. Country and currency are registry data, never hard-coded in the contract, SDK, or app.

Full depth lives in the canonical docs: ARCHITECTURE_ESSENTIALS.md, ARCHITECTURE.md, PRD.md, and the ADR index. This site summarizes; those files are the source of truth.
